# Writing Ready Briefs

A ready brief is Triage's single-slice handoff for an issue or configured PR
moving to `ready-for-agent` or `ready-for-human`. The source retains
commitment authority; tracker state is navigation metadata; the brief carries
the verified execution context. For a PR, describe the bounded work left on
the existing diff.

Prefer one independently completable vertical behavior slice. Use a support
slice only when it names the delivery slice it observably unblocks or
de-risks. Use a technical migration stage only when compatibility requires an
operable intermediate state. A tracer bullet is a learning role, not another
slice type.

Describe durable behavior and caller-facing Interfaces rather than file
choreography. Include only source-triggered engineering obligations and point
to the Engineering Contract for generic discipline.

## Template

```markdown
> *This was generated by AI during triage.*

## Codex-Ready Brief | Human-Ready Brief

**Category:** bug / enhancement
**State:** ready-for-agent / ready-for-human
**Recipient:** agent / human
**Work-unit form:** vertical behavior slice / support slice / technical migration stage
**Learning role:** tracer bullet / none
**Migration phase:** expand / migrate / contract / not applicable
**Summary:** one-line bounded outcome

### Intent

**Desired behavior and Commitment Boundary:**
Observable outcome, acceptance authority, public or data contracts, and
prohibited behavior.

**Acceptance criteria:**

Operational and observable; use exact owner pointers instead of restating
governed semantics.

- [ ] Specific observable criterion 1
- [ ] Specific observable criterion 2

**Non-goals:**
- Adjacent behavior that remains unchanged

### Grounding

**Current behavior and evidence:**
- Observation: confirmed / not-confirmed / partial / insufficient-evidence
- Readiness authority: normal / maintainer-override
- Evidence and residual uncertainty:

**Source Trace:**
- Request and decision-bearing comments
- Prior triage notes
- Relevant code, interfaces, tests, or PR diff
- Domain, ADR, research, prototype, or rejection pointers

**Repository grounding:**
- Current behavior owner and representative entry path
- Relevant Interface or Seam and Repository Reuse

### Correctness

Only applicable Invariants, Trust Boundaries, supported states, edge or error
behavior, failure or recovery, compatibility, environmental, observability,
security, privacy, or measured-claim obligations; otherwise `not applicable`.

### Scope And Proof

**Expected durable write scope:**
Modules, Interfaces, commands, configuration, or docs; not a mandatory file
list.

**Scope fence:**
Authorized behavior and coupled surfaces; adjacent work returned.

**Proof responsibility:**
- Proof Seam and concrete proof lane
- Canonical test owner or proof surface
- Reuse / extend / add; a new test requires a distinct responsibility

### Delivery

**Dependencies and order:**
- Parent or source:
- Blocked by:
- Parallel safety: independent / likely overlap / serialize because...

**Human-required act and completion evidence:** ready-for-human only; otherwise
`not applicable`.

### Change Closure

**Displaced surfaces:** implementation, caller, registration, export, flag,
test, configuration, documentation, or migration made obsolete; otherwise
`not applicable`.

**Retained compatibility:** path, owner, reason, proof, and Removal Trigger;
otherwise `not applicable`.
```

## Ready Gate

Complete only when one bounded slice has a valid work-unit form; the
Commitment Boundary and Source Trace are settled; observation status and
readiness authority are honest; applicable correctness obligations and
prohibited behavior are explicit; acceptance is operational and observable;
grounding, dependencies, expected write scope, parallel safety, scope fence,
Proof Seam, proof lane, and proof responsibility are usable; Change Closure is
accounted for; and a human brief names the required human act and completion
evidence.

An existing brief may be reused only after its source, evidence, dependencies,
scope, and gate remain current.

## Branch Emphasis

| Branch | Emphasize |
| --- | --- |
| Bug tracer | Trusted reproduction, suspected boundary, and regression responsibility |
| Enhancement vertical slice | Desired outcome, selected value, and acceptance proof |
| Enhancement tracer | Early feedback or load-bearing risk through a thin real path |
| Support slice | Smallest safe enabling change, blocked boundary, and observable validation |
| Technical migration stage | Compatibility obligation, phase, operable intermediate state, and rollback proof |
| PR finish | Remaining work, unresolved feedback, and merge-ready proof |
