# Native spawning

Use before the first routed spawn on a host, after a relevant capability change,
or when observed routing disagrees with the request. Reuse known host facts;
the selected execution workflow still owns team size, custody, and review sequence.

## Express the route

Follow the exposed tool contract and pass model and effort together. Current
Codex V2 spawning uses `model`, `reasoning_effort`, and `fork_turns="none"` for
routed fresh contexts; configuration files use `model_reasoning_effort`.
Do not copy historical keys, numeric fork values, or hidden arguments.

A task name does not select a configured agent role. Use supported role selection
and inspect its model/effort settings when relevant: custom-role settings can
take precedence over spawn values. Skill `agents/openai.yaml` does not enforce
child-model settings. Routing alone authorizes no global configuration edits.

## Supply the assignment

A fresh child needs the accepted outcome, scope and authorized effects, material
constraints, accessible sources, candidate/base identity, write ownership,
required verification, and expected return. Follow the calling workflow's
assignment contract and supply context the child cannot retrieve; omit unrelated
conversation history.

If a child is authorized to delegate, carry both shared routing and the selected
execution rules into its descendants, with their remaining scope. Neither this
reference nor a route grants delegation authority. Preserve host concurrency
limits and the execution owner's dispatch rules.

## Continue and verify selection

Reuse workers for coherent follow-ups while their configuration remains
appropriate. When a changed assignment requires a different route, use supported
configuration controls or transfer the assignment and useful evidence to a newly
routed worker under the execution owner's custody rules. Follow-up message text
alone does not change a worker's model or effort.

Recheck configuration when a role, host, resume behavior, or observed mismatch
makes selection uncertain.
If the intended pair cannot be expressed, use an available supported role only
when it selects that pair; otherwise report the limitation and continue
independent authorized work. A required unavailable reviewer remains incomplete.

Prefer runtime/configuration evidence over a child's self-description. Distinguish
requested, stored, and effective settings; report when only the request is visible.
Keep a selected Ultra mode unchanged rather than inferring that a reported effort
label selects or replaces that mode. No new telemetry system is required.

[Official subagent guidance](https://learn.chatgpt.com/docs/agent-configuration/subagents)
supplies host configuration context; the displayed tool contract governs the run.
