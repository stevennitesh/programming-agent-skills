# Active delivery revisions

Read only when accepted meaning or acceptance must change while tickets, workers,
or delivery proof already depend on the current revision.

## Identify affected work

Establish the accepted source revision, changed commitments, active tickets or
assignments, landed work, and evidence that depends on the old meaning.

Keep a proposed revision distinct from the currently accepted contract until its
owner settles the change. Do not redefine success, edit an active worker's
assignment, release claims, or alter execution state without the execution owner's
authority.

## Coordinate the revision

When authorized, the execution owner pauses or quiesces affected work before
changing its contract. Reconcile the accepted source and dependent acceptance or
assignments together.

Invalidate only proof and completion claims affected by the changed contract.
Preserve unaffected work and history. A former completion verdict does not prove
the revised outcome.

Resume affected work only against the reconciled accepted revision.

## Return the revision state

Report the changed commitments, affected work, invalidated evidence, remaining
implementation or proof, and whether execution can safely resume.
