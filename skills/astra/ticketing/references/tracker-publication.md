# Tracker publication and repair

Use for authorized tracker publication or repair. This reference owns mutation
mechanics; the calling mode/workflow determines disposition, decomposition, and
authority.
Follow repository tracker, relationship, readiness, label, and closure conventions;
a draft is not a published graph.

## Prepare only the authorized effects

Resolve affected projects, items, relationships, states, readiness, and ownership.
Inspect equivalent work before creating; title similarity alone is insufficient.
Bound which bodies, labels, links, or states may change and preserve unrelated
content and active claims. Coordinate changes to active assignments or ownership
with their execution owner.

When accepted meaning changes under active tickets, workers, or proof, use
[Active delivery revisions](../../shape-work/references/active-delivery-revisions.md)
before reconciling affected tracker content and claims. Prepare the exact requested
changes before mutation. Missing or incompatible setup leaves a usable
draft and publication gap. Use existing authority; ask only about prepared effects
requiring additional approval, without reconfirming unchanged authorized work.

## Apply and verify

Refresh affected state when intervening activity matters, or use supported
conditional writes. Reconcile drift instead of overwriting it. Reuse matching
items, create only missing work, and bind relationships to confirmed identities.
Use configured native relationships; prose cannot replace required links.

Choose individual, batched, or atomic operations for tracker capabilities and
policy, without a universal per-item sequence. Establish context and relationships
before readiness, and repair relationships before closure can falsely unblock
dependents. Keep new or materially revised assignments non-ready until their body
and required links are verified. Apply the shared
[Work-item brief](work-item-brief.md) before readiness; human-only work does not
authorize an agent to take the human action.

Read back affected content, states, relationships, and ownership as repository
policy requires. Verify consequential results independently of write receipts,
derive the actual starting set from the observed graph, and retain the source-to-
published identity mapping. Confirm accessible source context remains usable to
the next actor. Add attribution only when policy requires it.

For version-controlled local tickets, identify the canonical checkout. Publication
does not imply a Git commit or make worker copies independent tracker authorities.

## Recover from uncertain effects

After a partial, failed, or indeterminate mutation, stop dependent writes and
inspect actual state. Resume from confirmed identities without duplicate creates,
comments, or successful changes. Do not blindly replay publication, release an
ambiguous claim, close a parent, or alter unrelated ownership to match the plan.
Claim completion or rollback only when observed state supports it. Finish with
verified requested effects and explicit remaining uncertainty.
