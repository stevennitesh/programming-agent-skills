# Deploy Campaign

Use this method only when either the user explicitly invokes `Run Deploy
Campaign on <skill>` or a Fresh Composition Epoch issues a dependency-ready
canonical contract slice as part of already-authorized epoch execution. It is
one controllerless authoring method organized by four ordered reasoning and
proof obligations:

```text
Contract Lock -> Candidate Lock -> conditional Behavioral Proof -> Release
```

These are reasoning and proof obligations, not persisted semantic lifecycle
state. Do not create a campaign manifest, stage record, status token, resume
protocol, repair counter, migration adapter, or parallel workflow. Historical
campaign artifacts are inert evidence: do not interpret, mutate, resume,
release, or migrate them.

The campaign owner retains decisions, user interaction, and final synthesis.
Use fresh-context delegation only for bounded read-only evidence or behavioral
samples; keep candidate mutation serialized. Preserve unrelated work.

## Contract Lock

Bind the intended behavior from the issue, specification, applicable current
authority record, real callers and relationships, compatibility obligations,
delivery authority, and explicit exclusions. When a Fresh Composition Epoch
supplies an applicable frozen contract slice, treat it as an authority record,
not as campaign state.

Trace every acceptance commitment through the real caller to
an observable proof seam before choosing an edit. Reuse prior evidence only
when its complete candidate, claim, inputs, model, host, reasoning
configuration, tools, authority, environment, rubric, and identity of each
proof check still match.

Research is conditional. Run one bounded `$research` inquiry only when Contract
Lock identifies a decision-relevant source, method, concept, or hypothesis gap
that current applicable evidence cannot close. Research informs the candidate;
it never proves wording efficacy or forces a candidate change. If required
intent or authority is unsettled, return the exact gap and stop.

## Candidate Lock

Use `$writing-for-agents` to build the smallest
acceptance-complete candidate in the canonical source or a clearly isolated
candidate root. Freeze the exact candidate bytes and affected dependency
identities. Do not mutate the installed mirror to obtain proof.

Before any behavioral dispatch, canonical promotion, or installation, run
every applicable structural, relationship, compatibility, and integration
check against those exact bytes, including checks at the real caller.
Prefer an existing parameterized proof seam that accepts the candidate root;
a check that silently resolves current canonical bytes proves only current
canonical behavior.

A failed applicable check stops the campaign with zero behavioral dispatch
and zero promotion. Correct an in-scope candidate defect, freeze the changed
bytes again, and rerun invalidated deterministic proof. Return `blocked` or
`partial` when correction requires new intent, authority, or scope.

For a deterministic/no-change result, bind the current canonical bytes as the
candidate, run applicable deterministic proof, and Return `no-change` with
zero research, zero behavioral sampling, and zero pruning. Do not manufacture
work merely to advance an obligation.

## Behavioral Proof

Skip this obligation unless the user explicitly requested behavioral testing.
When requested, invoke the protocol at
[`skills/custom/writing-for-agents/references/BEHAVIOR-EVALS.md`](../../../skills/custom/writing-for-agents/references/BEHAVIOR-EVALS.md)
only for a claim that exact wording changes invocation, judgment, action,
context loading, Return, or completion. Without that request, make no wording
efficacy claim.

Freeze control and candidate bytes and use the protocol's registered control,
fresh isolated contexts, adaptive sampling gate, wrong-condition boundary, and
single evaluation decision. Accept the candidate only when the observed
decision no weaker than the control under the fixed rubric and the protocol
admits it. A missing control deficit stops candidate sampling; an unsupported,
ambiguous, or regressing claim keeps the control or current canonical behavior.

For mutation, preservation, read-back, partial-failure, or recovery claims,
exercise the exact candidate with real disposable state. Test doubles or prose
traces do not establish those effects. Expand proof only for a failed control
or a genuinely distinct changed mechanism.

## Release

Revalidate that the candidate bytes and proof dependencies still match
Candidate Lock. Perform one cheap cut scan. When no concrete material cut is
available, run zero pruning. When a material cut exists, freeze the tested
candidate as control and prove only the affected behavior; retain the tested
candidate for any ambiguous, regressing, or unproved cut.

Promote only the exact Candidate Lock bytes, or the exact behaviorally proved
material-cut bytes, into the canonical skill. Read back the complete canonical
package and rerun the applicable deterministic integration proof. Any byte
drift invalidates the affected proof and blocks Release.

`$writing-for-agents` stops after canonical proof. Installation dry-run,
synchronization, and parity require installation authority and use the existing
installer owner. Git staging, commit, and push require separate Git-delivery
authority. Git delivery remains separately authorized. Never infer either
authority from a bare Deploy Campaign request.

Return `complete`, `partial`, `blocked`, or `no-change` with the exact candidate
identity, research or behavioral branch taken, deterministic and real-state
proof, canonical mutations, deliberate non-changes, skipped foreign work, and
residual risk.
