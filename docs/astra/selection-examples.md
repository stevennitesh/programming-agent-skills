# Astra skill selection examples

These are canonical **selection boundary** examples for the current managed Astra
pack. They help maintainers and reviewers distinguish a skill's intended request
from its nearest realistic non-match.

They are not complete procedures or an additional router. Each
[skill entry point](../../skills/astra/) remains the execution authority, and the
frontmatter description remains the host-facing discovery contract. For
explicit-only skills, the canonical request includes the skill handle. For
automatically selectable skills, the request is shown in ordinary language.

| Skill | Canonical request | Expected behavior | Nearest non-match |
| --- | --- | --- | --- |
| [$audit-codebase](../../skills/astra/audit-codebase/SKILL.md) | `$audit-codebase Map this repo and show evidence-backed maintainability candidates; do not implement them.` | Map or audit the selected baseline, support findings with current-code evidence, and leave implementation unstarted. | `Review this PR for regressions.` That is change-review because the subject is a fixed change candidate. |
| [$change-review](../../skills/astra/change-review/SKILL.md) | `Review this branch against main for correctness and maintainability problems introduced by the change.` | Fix the candidate identity, judge changed behavior against accepted obligations, and return evidence-backed findings without unrelated baseline cleanup. | `Audit the whole repo for architecture debt.` That is audit-codebase because there is no selected change candidate. |
| [$codebase-design](../../skills/astra/codebase-design/SKILL.md) | `Decide where retry state should live and what interface should own it before I implement this feature.` | Resolve the bounded technical ownership/interface decision and return an implementable architecture direction or precise unresolved assumption. | `Decide what users should see after a partially saved import.` That is shape-work because the unsettled decision is product behavior. |
| [$context-hygiene](../../skills/astra/context-hygiene/SKILL.md) | `$context-hygiene Audit the persistent agent context for this repo and reconcile stale or duplicated guidance.` | Decide what deserves durable context, keep one trustworthy owner, and apply only the requested scoped cleanup. | `Rewrite this AGENTS.md paragraph for clarity.` That is writing-for-agents because the artifact and desired edit are already scoped. |
| [$cost-aware-coding](../../skills/astra/cost-aware-coding/SKILL.md) | `$cost-aware-coding Implement the accepted retry plan while minimizing Astra lead-token churn.` | Keep consequential reasoning and final review with Astra, route substantial implementation to Sol, and use Luna only where bounded work is genuinely cheaper. | `Implement this two-line null check.` Direct coding is cheaper than delegation overhead. |
| [$diagnosing-bugs](../../skills/astra/diagnosing-bugs/SKILL.md) | `This failure appears only under concurrent retries. Find the causal mechanism and fix it if the evidence supports a repair.` | Establish a falsifiable causal explanation, distinguish credible alternatives, and repair the causal owner when authorized. | `The stack trace points to a misspelled variable; fix it.` An obvious local fix does not need the diagnosis workflow. |
| [$hillclimb](../../skills/astra/hillclimb/SKILL.md) | `$hillclimb Reduce p95 import latency without changing results; use comparable measurements and keep only proven improvements.` | Freeze the objective and keep rule, establish a valid baseline, iterate interpretable candidates, and retain only measured wins. | `Check once whether batching 100 records is faster than 10.` That is a bounded prototype unless an optimization loop is actually requested. |
| [$parallel-implement](../../skills/astra/parallel-implement/SKILL.md) | `$parallel-implement Implement these three accepted independent tickets concurrently and integrate them.` | Admit only genuinely independent work, give writers exclusive custody, integrate serially, and prove the composed result. | `Implement this one feature.` A single coherent change should stay direct or serial. |
| [$prototype](../../skills/astra/prototype/SKILL.md) | `Run a bounded experiment to determine whether SQLite WAL mode preserves the concurrency behavior this design needs.` | Define the deciding observation, preserve the mechanism that matters, run the smallest faithful experiment, and return the bounded evidence. | `Keep tuning database settings until p95 is under 50 ms.` That is hillclimb because it requests iterative optimization. |
| [$repo-bootstrap](../../skills/astra/repo-bootstrap/SKILL.md) | `$repo-bootstrap Reconcile this repo's agent guidance after the project moved from npm to pnpm and tracker rules changed.` | Inspect the repository guidance surface, verify its factual owners, and create or reconcile the smallest current setup. | `Rewrite this one worker prompt so acceptance is clearer.` That is writing-for-agents because repository setup is not changing. |
| [$research](../../skills/astra/research/SKILL.md) | `Compare the documented retry guarantees of SQS and Pub/Sub and recommend which fits these constraints.` | Match claims to appropriate sources, test the conclusion against counterevidence, and return a supported comparison with limits. | `Benchmark both clients in this repo to observe actual throughput.` That requires a new observation, so use prototype for a bounded experiment. |
| [$resolving-merge-conflicts](../../skills/astra/resolving-merge-conflicts/SKILL.md) | `Resolve the conflicts in this active rebase and continue it, preserving both intended changes.` | Observe the active Git operation, reconcile intended combined behavior, prove the resolved candidate, and reach only the authorized endpoint. | `Merge feature-x into main from a clean worktree.` Starting an ordinary integration is not conflict resolution. |
| [$shape-work](../../skills/astra/shape-work/SKILL.md) | `$shape-work Clarify retry behavior for partially saved imports, including what users see and how acceptance distinguishes success.` | Settle consequential product behavior, scope, constraints, domain meaning, and discriminating acceptance without inventing technical policy unnecessarily. | `Choose whether retry state belongs in the service or repository layer.` That is codebase-design because the question is technical ownership. |
| [$to-tickets](../../skills/astra/to-tickets/SKILL.md) | `$to-tickets Turn this accepted migration plan into the fewest useful GitHub issues with real dependencies.` | Preserve settled meaning, create cohesive independently checkable work units, and represent only real predecessor dependencies. | `$triage Classify this newly reported issue.` Raw tracker intake belongs to triage. |
| [$triage](../../skills/astra/triage/SKILL.md) | `$triage Classify this incoming issue, determine the honest next state, and apply only the authorized tracker changes.` | Use bounded evidence to choose one configured disposition, preserve one-category/one-state and blocker invariants, apply effects idempotently, and read them back without starting downstream work. | `Split this accepted feature into implementation tickets.` Settled delivery decomposition belongs to to-tickets. |
| [$verification-harness](../../skills/astra/verification-harness/SKILL.md) | `$verification-harness Build a repeatable browser harness that launches the app, drives login with a test identity, captures visible evidence, and cleans up.` | Create durable repository-owned tooling that binds the candidate, proves its checks can fail, drives the real supported surface, classifies harness/product/environment failures, preserves evidence, and cleans up safely. | `Guide me through entering my private production credential and finishing provider dashboard steps.` Human-private operation belongs to wizard. |
| [$wizard](../../skills/astra/wizard/SKILL.md) | `$wizard Create a local guided script for configuring this API integration; I must enter the secret and finish the provider dashboard steps myself.` | Build and validate a human-operated procedure that keeps private input and manual effects outside agent-visible execution. | `Automate the same flow end to end with an isolated test account.` Agent-operated repeatable verification belongs to verification-harness. |
| [$writing-for-agents](../../skills/astra/writing-for-agents/SKILL.md) | `Rewrite this AGENTS.md section so a fresh coding agent knows when to run the project-specific verifier.` | Write or audit the already-scoped instruction artifact for the receiving agent, preserving authority, boundaries, and completion evidence. | `$repo-bootstrap Set up agent guidance for this new repository.` Repository-level setup and routing belong to repo-bootstrap. |

## Maintenance rule

Keep exactly one row per managed Astra skill. Update a row when a discovery
boundary materially changes; do not churn examples for wording-only edits. A
positive example demonstrates eligible intent, while the near-miss should exercise
the closest realistic boundary rather than an obviously unrelated task.
